Detailed Description

captures an authoritative copy of the room's player-identity and ownership state, uploads it into the relay's (PurrLay) RAM via PurrTransport.UploadRoomSnapshot, and restores it on the promoted host. This closes the gap where a transferring client reconnected against an incomplete replica and got a fresh PlayerID + duplicate character: the snapshot is authoritative, so cookie→PlayerID and per-object ownership are correct regardless of what was visibility-culled or in-flight at host loss.

Registered on BOTH module stacks. The promotion path migrates the live client modules into the server collection (server-only modules are dropped), so the client-side instance — the one that stashed the downloaded snapshot — is the one that ends up on the promoted host and applies it. Capture only runs server-side; restore runs in PostPromoteToServerModule, which executes before the transport's auto-MIGRATION_READY.

Current scope: players (cookie↔PlayerID + id counter + last NetworkID) and ownership (per-scene identity→owner). Reconstructing visibility-culled objects from a full hierarchy snapshot is still future work — with the recommended host-migration rules (identitiesAlwaysVisible/scenesAlwaysPublic) those objects already exist on the promoted host, so ownership restore re-attaches to them.
